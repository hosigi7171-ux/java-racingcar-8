* [x] 각 자동차는 **0부터 9 사이의 무작위 숫자**를 생성하고, **4 이상이면 전진**한다.
* [x] 사용자가 **시도할 횟수**를 입력받으면 해당 횟수만큼 **자동차들이 전진하거나 멈추는 경주**가 진행된다.
* [x] **전진한 자동차**는 그 이름과 함께 **`-`로 전진 거리**를 출력한다.
* [x] **최종 우승자**를 출력하며, 우승자가 여러 명일 경우 쉼표(,)로 구분하여 출력한다.
* [x] 사용자가 잘못된 값을 입력할 경우 **IllegalArgumentException**을 발생시키고, 애플리케이션이 정상 종료되도록 구현했다.

### 입출력 요구 사항

* [x] 입력:

    * 경주할 **자동차 이름**을 쉼표(,)로 구분하여 입력받는다.
    * 시도할 **횟수**를 입력받는다.
* [x] 출력:

    * **차수별 실행 결과**를 출력한다.

        * 예시: `최종 우승자 : pobi`
        * 또는 **공동 우승자**가 있을 경우: `최종 우승자 : pobi, jun`

### 1. 이번 주차 새로운 시도: TDD 도입
주마다 자체적으로 새로운 시도를 하고자 합니다.  
이번 주차에는 새로운 시도로 TDD(Test-Driven Development)를 처음 적용해보았습니다. 
설계를 먼저 하고 테스트 코드를 작성한 뒤 기능을 구현하는 과정은 생각보다 쉽지 않았습니다. 
설계가 충분히 구체적이지 않으면 테스트 코드를 작성하는 단계에서 막막함을 느꼈고, 
이를 통해 메서드 단위까지 어느 정도 설계를 구체화한 뒤 시작하는 것이 중요하다는 점을 깨달았습니다.

TDD 를 통해 얻은 장점도 분명했습니다. 
테스트 코드를 먼저 작성하며 기능을 구현하니 나중에 발생하는 기능적 오류가 줄었고, 
코드 구조를 테스트 친화적으로 개선하면서 인터페이스 활용이나 패키지 분할, 
객체 지향적인 설계까지 자연스럽게 적용할 수 있었습니다. 
반면, 간단한 프로젝트나 마감이 촉박한 경우에는 TDD 방식이 비효율적이라고 느껴지기도 했고, 
테스트 코드 작성 자체가 목적이 된 것처럼 느껴지는 순간도 있었습니다. 
앞으로 모든 프로젝트에서 TDD 를 적용할지는 고민이 필요하지만, 
코드 구조와 품질을 고민하는 데 큰 도움이 된 경험이었습니다.

### 2. 코드 리뷰 피드백 반영
1주차 코드 리뷰에서 받은 피드백을 이번 프로젝트에 최대한 반영하려고 노력했습니다.
- 에러 메시지를 Enum 으로 관리하여 가독성과 유지보수성을 높였습니다.
- 코드 스타일 일관성을 위해 한 줄이라도 중괄호를 처리했습니다.
- 생성자 주입(AppConfig)을 적용하여 DIP 와 OCP 를 준수하고 테스트 용이성을 확보했습니다.

메서드 세분화 등은 일부 적용했으며, 나머지(StreamAPI, 일급 컬렉션, 정규표현식 등)는 추가 학습 후 
점진적으로 적용할 계획입니다. 피드백을 반영하며 코드 품질이 개선되는 것을 체감했고, 
앞으로도 적극적으로 수용하는 습관을 이어가고자 합니다.

### 3. 자체 목표: 생성형 AI 최소화
이번 프로젝트에서도 마찬가지로 설계, 구현, 테스트, 디버깅, 1차 리팩토링까지 생성형 AI 사용을 최소화하였습니다. 
그 과정은 시간이 오래 걸렸지만, 스스로 고민하고 문제를 해결한 경험이 기억에 오래 남았습니다. 
직접 구현하고 디버깅하며 missions-utils 라이브러리 까지 살펴보며 얻은 학습 경험은 
단순히 AI를 활용하는 것보다 훨씬 깊이 남았고, 장기적인 성장에 큰 도움이 되었다고 느꼈습니다.

### 4. 설계의 중요성
TDD 를 수행하며 설계의 중요성을 다시 한번 실감하였습니다. 
초기 설계가 충분히 최적화되지 않으면 테스트 코드 작성과 구현 과정 모두 어려워졌습니다. 
앞으로는 설계 단계에서 더 많은 시간을 투자하여 구체적이고 테스트 가능한 구조를 만드는 데 집중하고자 합니다.

## 설계 관련 고민
1. **우승자 계산 방식**
    - 레이스를 진행하면서 우승자 리스트를 갱신할 수도 있지만, 테스트와 효율성을 고려하면 **레이스 종료 후 우승자를 한 번 계산**하는 것이 더 적절.
    - `RaceRoundManager`에서 전부 관리해도 과제 요구사항은 충족 가능하지만, 추후 확장성을 위해 우승자 출력/레이스 진행을 분리할 수도 있음.
    - 테스트 용이성을 위해, `RacingGame`에서 `RaceRoundManager`의 메서드를 호출하여 자동차 리스트를 갱신하도록 설계.

## 요구사항 해석
2. **시도 횟수**
    - +5000과 같은 큰 수는 유효하지 않음.

3. **자동차 이름 입력**
    - `"a124 , 321, bdf "`는 유효.
    - `"   , abc, dde"`와 같은 경우, 공백만 있는 이름이나 빈 문자열은 **테스트 시 `missions-utils`에 있는 NsTest 의 output() 에서 trim()으로 제거됨** → 따라서 공백/빈 문자열은 에러 처리.
    - 자동차 이름 중복은 허용.

## InputReader 테스트 관련 고민
4. **InputReader 테스트 시 문제**
    - `InputReaderTest`에서 System.in을 테스트용 버퍼로 바꾸면 개별 테스트는 통과하지만, 여러 테스트를 연속 실행하면 실패.
    - 원인: `missions-utils`의 `Console` 내부 Scanner가 **싱글톤 패턴**이어서 System.in을 한 번만 참조함.
    - 해결 방법:
        1. `Console.close()`로 Scanner를 닫으면 InputReaderTest 통과 → 하지만 System.in까지 닫혀 ApplicationTest 실패.
        2. Stub 대체 불가 → Console이 외부 라이브러리이고, private 생성자 및 상속 불가.
        3. **Reflection으로 Console 내부 Scanner를 강제 초기화** → 모든 테스트 정상 수행.

## 출력 테스트 문제
5. **출력 문자열 차이**
    - 예상 문자열과 실제 출력이 겉보기에는 동일하지만, 개행문자 차이(`\n` vs `println` 의 `System.lineSeparator()`) 때문에 테스트 실패.
    - 해결:
        - 문자열 결합 방식 수정
        - 필요 시 `StubRaceDisplay`를 활용해 테스트용 출력 단순화할 수도 있을 것.

## 의존성 있는 유닛 테스트
6. **RaceRoundManager 테스트**
    - Mockito 사용 불가 환경
    - 대신 **Stub 구현 방식**으로 의존성 분리 및 테스트 가능하도록 함

## 기능 설계서

1. **RacingCar**: 자동차 객체를 관리한다. 이름과 전진 거리를 저장한다.
2. **RacingGame**: 전체 게임 흐름을 관리한다.

    * **InputReader**: 사용자로부터 자동차 이름과 시도 횟수를 입력받는다.
    * **InputValidator**: 입력값의 형식과 유효성을 검증한다.
    * **RaceRoundManager**: 경주를 차수별로 진행하며, 각 차수마다 자동차가 전진하는지 결정한다.
    * **RaceDisplay**: 경주 현황을 화면에 출력한다.
    * **ResultWriter**: 최종 우승자를 출력한다.

| 단계  | 기능 설명                             | 클래스명                   |
| --- | --------------------------------- | ---------------------- |
| 1   | 자동차 이름을 입력받는다                     | **`InputReader`**      |
| 2   | 이름의 유효성을 검증한다                     | **`InputValidator`**   |
| 3   | 시도 횟수를 입력받는다                      | **`InputReader`**      |
| 4   | 각 차수마다 자동차 리스트를 순회하며 경주를 진행한다     | **`RaceRoundManager`** |
| 4-1 | 랜덤한 숫자를 생성하고, 4 이상이면 전진한다         | **`RaceRoundManager`** |
| 4-2 | 전진 거리가 더 멀리 나갔다면 최대 거리와 우승자를 갱신한다 | **`RaceRoundManager`** |
| 4-3 | 경주 현황을 출력한다                       | **`RaceDisplay`**      |
| 5   | 최종 우승자를 출력한다                      | **`ResultWriter`**     |

### 패키지별 역할

- **racingcar.config** : 앱 설정 및 의존성 주입 구성
- **racingcar.constants** : 공통 상수 정의
- **racingcar.display** : 레이스 진행 상태를 출력
- **racingcar.domain** : 자동차 도메인 및 레이싱 게임 진행 관리
- **racingcar.generator** : 숫자 생성 기능 제공
- **racingcar.io** : 입력과 출력 처리
- **racingcar.service** : 단일 라운드 진행 및 우승자 결정
- **racingcar.validator** : 입력 검증 기능 제공
- **test 패키지** : 단위 테스트 및 테스트용 스텁 구현
